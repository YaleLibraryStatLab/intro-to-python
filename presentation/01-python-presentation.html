Playing the ballgame early

You learn Python today by doing statistics: a junior version of the whole game, start to finish.

What you will learn

  • read real data
  • compare two groups
  • test the difference
  • fit a regression

Twenty-eight functions and methods, and that is the whole list.

It is not a crash course in Python programming, or in hypothesis testing.

Today’s question

Did states that expanded Medicaid in 2014 have lower working-age mortality than states that did not?

Today’s Ballgame

Explore: What does mortality look like across states that expanded Medicaid and those that did not?   → plt.hist(), .boxplot(), group means

Test: Is the difference in these states bigger than chance would produce?   → stats.ttest_ind()

Check: does the answer to our second question depend on unreasonable assumptions?   → permutation test

Extend: how can we formally express and model these differences?   → smf.ols("rate ~ expanded")

Two things to name first

Every line today is built from two kinds of thing: objects and functions.

  • An object is something you made and gave a name to. It sits in the Variables pane until you overwrite it or restart Python.
  • A function does something. You give it a name, a pair of parentheses, and whatever it needs to know inside them.

Why the .notna() guard

A missing value answers False to every comparison, so NaN == 2014 quietly lands in the 0 group. The guard says so out loud: not missing, and equal to 2014.

The trap: Python does & before ==. Drop the parentheses and there is no error:

np.where(d2014["yaca"].notna() & d2014["yaca"] == 2014, 1, 0).sum()
np.int64(0)

Every county lands in “did not expand”. Silent wrong answers are worse than errors.

The template: y broken down by x

One pattern does most of the work today.

data.groupby(x)[y].goal()

Read groupby(x), by=x, and ~ x as “broken down by”.

states.groupby("expanded")["rate"].mean() group means
states.boxplot(column="rate", by="expanded") a picture

The t-test is the odd one out: it wants the two groups handed over one at a time.

Step 4c: weight by population

A rate is deaths over people. To get a state’s rate, turn each county’s rate back into deaths, add up the deaths and the people by state, and divide once.

d2014["deaths"] = d2014["crude_rate_20_64"] * d2014["population_20_64"] / 1e5

states = d2014.groupby(["state", "expanded"],
                       as_index=False)[["deaths", "population_20_64"]].sum()
states["crude_rate_20_64"] = states["deaths"] / states["population_20_64"] * 1e5
states = states.sort_values("state")
states.shape
(39, 5)

The template again: d2014.groupby(x)[y].sum(), where x is state and expansion status and y is deaths and population. Two of each, so both go in a list, [ ].

Sorting changes nothing today, but the shuffling in step 7 depends on row order. Make the order a decision you can see.

as_index=False keeps state and expanded as ordinary columns, so we get a plain table. Leave the parentheses off .sum and Python prints <bound method ...> instead of an answer.

TEST · Step 6: the test you already know

result = stats.ttest_ind(states["crude_rate_20_64"][states["expanded"] == 1],
                         states["crude_rate_20_64"][states["expanded"] == 0],
                         equal_var=False)
result
TtestResult(statistic=np.float64(-1.5434721815517884), pvalue=np.float64(0.13180569962554284), df=np.float64(34.632273771767))
result.confidence_interval()
ConfidenceInterval(low=np.float64(-90.72705983416654), high=np.float64(12.371747161396911))

Read all of it. The interval tells you the size of the gap the data supports. The p-value never does.

equal_var=False asks for Welch’s t-test, which does not assume the two groups are equally spread out.

Which way round?

We computed diff_obs = −39. The interval says −91 to +12. Same sign.

ttest_ind(a, b) subtracts a − b, and we handed it the expanded states first: group 1 − group 0, the same way round as diff_obs.

Swap them and every sign flips, with no warning. When a sign looks wrong, check which way round the subtraction went.

CHECK · Step 7: what does p = 0.13 actually mean?

Most of us walk in carrying this one:

“p is the probability the result is due to chance.”

It has the logic backwards.

It assumes chance is all there is, and then asks:

if expansion made no difference at all, how often would luck alone hand us a gap as big as ours?

CHECK · Step 7: so let’s build one

  • The null hypothesis says the labels are meaningless.
  • So let’s make them meaningless by shuffling which states expanded.
  • Do that a thousand times, and we have a thousand worlds where the policy did nothing.
  • Then just count how many of them beat our real result.

We don’t have to trust a formula for this. We can just do it.

Step 7: one fake world

rng = np.random.default_rng()
shuffled = rng.permutation(states["expanded"])

(states["crude_rate_20_64"][shuffled == 1].mean() -
 states["crude_rate_20_64"][shuffled == 0].mean())
np.float64(-37.74574697362232)

rng is a random number generator: the thing that does the shuffling. Run it again:

shuffled = rng.permutation(states["expanded"])
(states["crude_rate_20_64"][shuffled == 1].mean() -
 states["crude_rate_20_64"][shuffled == 0].mean())
np.float64(-9.621431079807053)

That bouncing is sampling variation. You are looking straight at it.

Step 7: a thousand fake worlds

rng = np.random.default_rng(2026)
diffs = []
for i in range(1000):
    shuffled = rng.permutation(states["expanded"])
    diffs.append(states["crude_rate_20_64"][shuffled == 1].mean() -
                 states["crude_rate_20_64"][shuffled == 0].mean())
diffs = np.array(diffs)

The seed, 2026, makes the shuffling repeatable. for i in range(1000): runs the indented lines 1000 times; .append() keeps each answer. The indent is the grouping, so line it up exactly.

Step 7: and there it is

plt.figure()
plt.hist(diffs)
plt.axvline(diff_obs, color="red", linewidth=2)
plt.show()
(abs(diffs) >= abs(diff_obs)).mean()
np.float64(0.131)

A p-value you built out of shuffling and counting.

The t-test said 0.132. Not identical, and it shouldn’t be: 1000 shuffles is itself a sample. Same conclusion: not distinguishable from chance with 39 states.

That one line does three things

( abs(diffs) >= abs(diff_obs) ).mean()
abs() drops the minus sign, so we count both tails: past −39 and past +39. That is what “two-sided” means, and it is what ttest_ind() did.
>= gives a True/False for each of the 1000 shuffles
.mean() of True/False gives the proportion that are True, because True counts as 1

Drop the abs():

(diffs >= diff_obs).mean()
np.float64(0.915)

Our difference is negative, so this counts almost every shuffle. No warning, just a wrong number.

MODEL · Step 8: you need two numbers from that

Both on the expanded row:

coef −39.18 our difference in means, exactly
P>|t| 0.131 our p-value

Intercept, on the row above, is the mean of the group coded 0: the baseline. Everything else answers questions we haven’t asked.

A difference in means is a regression coefficient. t-test, permutation test, and regression: three ways of asking one question, and they agree.

equal_var=False is Welch’s correction, which is why the t-test’s df was 34.63 rather than 37. equal_var=True matches ols() to the decimal.

Step 9: why we used 39 rows and not 2,372

stats.ttest_ind(d2014["crude_rate_20_64"][d2014["expanded"] == 1],
                d2014["crude_rate_20_64"][d2014["expanded"] == 0],
                equal_var=False).pvalue
np.float64(5.687913728799441e-17)

That is the same test, run on the counties.

p is about 6e-17. Overwhelming, and wrong.

It thinks it has 2,372 independent observations. It has 39: every county in a state shares one policy decision.

When a p-value looks too good, ask how many independent things you actually measured.

Glossary: the twenty-eight functions and methods

Glossary: square brackets do four jobs

The one that catches everyone. Same symbol, four different meanings:

df["col"] pull one column out of a table counties["year"]
df[test] keep the rows where a test is True, in a table or a single column counties[counties["year"] == 2014]
s[label] pick one value by its label group_means[1]
["a", "b"] make a list; inside df[ ] it picks several columns [["deaths", "population_20_64"]]

Appendix

Inside the quotes: a path

"data/medicaid.csv"

" " make it a string: text, taken as-is. Without them, Python reads medicaid as the name of an object, goes looking, and fails.

data/ is a folder. Folder, slash, file: that is a path, directions to the file, starting from the folder you opened.

medicaid.csv is the file itself.

.csv is the extension: what kind of file it is. Comma-separated values, a table saved as plain text. pd.read_csv() reads this kind; an Excel .xlsx needs a different function. Finder and File Explorer hide extensions by default, so you may only see medicaid there.

Mac vs. Windows

The full path to the same file, on two laptops:

Mac /Users/you/intro-to-python/data/medicaid.csv
Windows C:\Users\you\intro-to-python\data\medicaid.csv
  • Ours skips all of that. data/medicaid.csv starts from the folder you opened, so it is the same on every laptop.
  • In Python, always write /, even on Windows. A lone \ can silently turn into a special character: in "data\new.csv", the \n becomes a line break, and Python goes looking for a file that does not exist. / never does that.

Set up Python, once

For anyone who arrives without a working setup. These go in the Terminal (Terminal → New Terminal), not your script. Copy them from the README; don’t retype them.

  1. Install uv, the tool that sets up Python for you:

    Mac:

    curl -LsSf https://astral.sh/uv/install.sh | sh

    Windows:

    powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

  2. Close that terminal (the trash-can icon) and open a new one, so it can find uv.

  3. Run uv sync.

  4. Pick the .venv Python in the top-right corner, then run scripts/00-check.py (Cmd/Ctrl+Shift+Enter). It should end with You're ready.

uv sync builds a .venv folder holding pandas, numpy, scipy, statsmodels, and matplotlib, in the versions this workshop was tested with. It downloads Python 3.12 for it if you need one. Already have a different Python, like 3.14? That’s fine: uv leaves it alone.
