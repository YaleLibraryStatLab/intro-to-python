Today’s question

Did states that expanded Medicaid in 2014 have lower working-age mortality than states that did not?

Today’s Ballgame

Explore: What does mortality look like across states that expanded Medicaid and those that did not?   → plt.hist(), .boxplot(), group means

Test: Is the difference in these states bigger than chance would produce?   → stats.ttest_ind()

Check: does the answer to our second question depend on unreasonable assumptions?   → permutation test

Module 1: I do

Two things to name first

Every line today is built from two kinds of thing: objects and functions.

  • An object is something you made and gave a name to. It sits in the Variables pane until you overwrite it or restart Python.
  • A function does something. You give it a name, a pair of parentheses, and whatever it needs to know inside them.

That is the whole vocabulary. Every line today is one or both.

Anatomy of a function call

pd.read_csv("data/medicaid.csv", index_col=0)

pd. says where the function lives: in pandas, the table library, which we load under the short name pd before step 1.

read_csv is the function name. It says what you want done.

( ) holds everything the function needs to know.

"data/medicaid.csv" is the first argument: which file to read.

index_col=0 is a named argument. It changes how the function behaves: treat the first column as row labels, not data. (Python counts from 0, so column 0 is the first one.) That is why we get 13 columns from a 14-column file.

, separates one argument from the next.

Two questions get you through any function: what do I want Python to do, and what does Python need to know to do it?

Inside the quotes: a path

"data/medicaid.csv"

" " make it a string: text, taken as-is. Without them, Python reads medicaid as the name of an object, goes looking, and fails.

data/ is a folder. Folder, slash, file: that is a path, directions to the file, starting from the folder you opened.

medicaid.csv is the file itself.

.csv is the extension: what kind of file it is. Comma-separated values, a table saved as plain text. pd.read_csv() reads this kind; an Excel .xlsx needs a different function. Finder and File Explorer hide extensions by default, so you may only see medicaid there.

Step 3: expansion is a state policy

Every county in Alabama has the same Medicaid policy as every other county in Alabama.

So the thing that varies is the state, not the county. Thirty-nine states decided; 2,372 counties did not each decide separately.

We need one row per state before we compare anything. That takes three moves: keep one year, label each state, then average to the state.

Step 3a: keep one year

d2014 = counties[counties["year"] == 2014]
d2014.shape
(2372, 13)

Square brackets with a True/False test inside keep the rows where the test is True. We asked for rows where year is 2014, and we get every column.

== asks is this equal to. It is a question, not an instruction — that is why it is doubled.

Reading a line, right to left

d2014 = counties[counties["year"] == 2014]

Longer lines are still one sentence. Start at the right:

  • counties[counties["year"] == 2014] says from counties, keep the rows where year is 2014 …
  • = says … and store it …
  • d2014 says … as d2014.

“From counties, keep the rows where year is 2014, and store that as d2014.”

Whatever is left of the = is the name you are giving to the result. If you can say a line out loud, you understand it. If you cannot, that is where to stop and ask.

Note the square brackets doing a second job: on the left of = they create a column rather than pulling one out.

Why the .notna() guard

States that never expanded have yaca = NaN: not a number, pandas’ mark for a missing value.

NaN == 2014 is False. In pandas a missing value answers False to every comparison, so it quietly lands in whichever group False means. Here that is the right group, and the guard says so out loud: not missing, and equal to 2014.

Now the trap. & means “and”, and Python does & before ==. Drop the parentheses and there is no error:

np.where(d2014["yaca"].notna() & d2014["yaca"] == 2014, 1, 0).sum()
np.int64(0)

Every county lands in the “did not expand” group.

Silent wrong answers are worse than errors. This is one of the most common ways pandas hands you one.

states_unwt = d2014.groupby(["state", "expanded"],

Read it left to right, one dot at a time: take d2014, group it by state and expansion status, take crude_rate_20_64, and average it.

["state", "expanded"] is a list: two names held as one thing. as_index=False keeps state and expanded as ordinary columns, so we get back a plain table.

.mean() with parentheses runs the method. Leave them off and you get the method itself, not an answer: Python prints <bound method ...> and moves on.

The template: y broken down by x

That idea is the most reusable thing you will learn today.

data.groupby(x)[y].goal()

Read groupby(x), by=x, and ~ x as “broken down by”.

TEST · Step 5: the test you already know

result = stats.ttest_ind(states["crude_rate_20_64"][states["expanded"] == 1],
                         states["crude_rate_20_64"][states["expanded"] == 0],
                         equal_var=False)
result
TtestResult(statistic=np.float64(-1.5434721815517884), pvalue=np.float64(0.13180569962554284), df=np.float64(34.632273771767))
result.confidence_interval()
ConfidenceInterval(low=np.float64(-90.72705983416654), high=np.float64(12.371747161396911))

Read all of it. The interval tells you the size of the gap the data supports. The p-value never does.

equal_var=False asks for Welch’s t-test, which does not assume the two groups are equally spread out.

Which way round?

We computed diff_obs = −39. The interval says −91 to +12. Same sign.

That is not luck. ttest_ind(a, b) subtracts a − b, and we handed it the expanded states first: group 1 − group 0, the same way round as diff_obs.

Hand them over the other way round and every sign flips, with no error and no warning. This catches everyone once. When a sign looks wrong, find out which way round the subtraction went before assuming you broke something.

statistic = −1.54 and df = 34.63 you can ignore today.

CHECK · Step 6: what does p = 0.13 actually mean?

Most of us walk in carrying this one:

“p is the probability the result is due to chance.”

It’s the most common answer, and it has the logic backwards. A p-value never tells you the probability that chance caused your result.

It assumes chance is all there is, and then asks:

if expansion made no difference at all, how often would luck alone hand us a gap as big as ours?

CHECK · Step 6: so let’s build one

  • The null hypothesis says the labels are meaningless.
  • So let’s make them meaningless by shuffling which states expanded.
  • Do that a thousand times, and we have a thousand worlds where the policy did nothing.
  • Then just count how many of them beat our real result.

We don’t have to trust a formula for this. We can just do it.

Step 6: one fake world

rng = np.random.default_rng()
shuffled = rng.permutation(states["expanded"])

(states["crude_rate_20_64"][shuffled == 1].mean() -
 states["crude_rate_20_64"][shuffled == 0].mean())
np.float64(6.1428020183844865)

rng is a random number generator: the thing that does the shuffling. Run it again:

shuffled = rng.permutation(states["expanded"])
(states["crude_rate_20_64"][shuffled == 1].mean() -
 states["crude_rate_20_64"][shuffled == 0].mean())

That bouncing is sampling variation. You are looking straight at it.

Step 6: a thousand fake worlds

rng = np.random.default_rng(2026)
diffs = []
for i in range(1000):
    shuffled = rng.permutation(states["expanded"])
    diffs.append(states["crude_rate_20_64"][shuffled == 1].mean() -
                 states["crude_rate_20_64"][shuffled == 0].mean())
diffs = np.array(diffs)

The seed, 2026, makes the shuffling repeatable. for i in range(1000): runs the indented lines 1000 times, and .append() keeps each answer. The indent is the grouping, so line it up exactly.

One thousand worlds in which the policy did nothing.

Step 6: and there it is

plt.figure()
plt.hist(diffs)
plt.axvline(diff_obs, color="red", linewidth=2)
plt.show()
(abs(diffs) >= abs(diff_obs)).mean()
np.float64(0.131)

Same plt.hist() from step 2, pointed at something new. That number is a p-value you built out of rng.permutation(), .mean(), and counting.

That one line does three things

( abs(diffs) >= abs(diff_obs) ).mean()
abs() drops the minus sign, so we count both tails: past −39 and past +39. That is what “two-sided” means, and it is what ttest_ind() did.
>= gives a True/False for each of the 1000 shuffles
.mean() of True/False gives the proportion that are True, because True counts as 1

Drop the abs() and see

(diffs >= diff_obs).mean()
np.float64(0.915)

0.915, not something near 0.07. Our difference is negative, so “shuffles at least as large as ours” counts almost all of them.

Python does not warn you. If you want the one-sided p in the direction of the effect, it is (diffs <= diff_obs).mean(). Getting this wrong returns a number, not an error.

Why it doesn’t exactly match ttest_ind()

Permutation gave 0.131. The t-test gave 0.132.

  • ttest_ind() assumes the difference follows a normal distribution. The shuffle does not. It does assume the labels could have been dealt out any other way, which is true here because each state chose once.
  • 1000 shuffles is itself a sample. Change the seed and the second digit moves. Run 10,000 if that matters to you.

Two methods, same conclusion: this difference is not distinguishable from chance with 39 states.

Step 8: why we used 39 rows and not 2,372

stats.ttest_ind(d2014["crude_rate_20_64"][d2014["expanded"] == 1],
                d2014["crude_rate_20_64"][d2014["expanded"] == 0],
                equal_var=False).pvalue
np.float64(5.687913728799441e-17)

That is the same test, run on the counties.

p is about 6e-17. Overwhelming, and wrong.

It believes it has 2,372 independent observations. It has 39. Every county in a state shares one policy decision, so those rows repeat 39 pieces of information rather than adding 2,372 new ones.

When a p-value looks too good, ask how many independent things you actually measured. It is usually fewer than the number of rows.

Glossary: the thirty-one functions and methods

Get data, look at it

Pictures

Build a grouping variable

Summarise

.mean() average, and on True/False a proportion
.sum() add up
.median() the middle value

What’s new in Module 2

Two things you have not seen:

Making groups from a number. Expansion came ready-made as 0/1. Poverty is continuous, so you split it at the median with np.where().

A result that runs off the page. Your observed difference may fall outside the whole null distribution. plt.axvline() widens the axis to fit it:

plt.hist(diffs)
plt.axvline(diff_obs, color="red", linewidth=2)   # stretches the x-axis if it must

So the red line may sit far out on its own. That empty space is the result, not a drawing glitch.

If (abs(diffs) >= abs(diff_obs)).mean() gives you 0, that is not p = 0. None of 1000 shuffles got that far, so report p < 0.001.

Two rules for your own work

Always open the folder. Never write os.chdir("/Users/you/..."). It works on exactly one computer, and not for long. Open the project folder and every path in your script stays relative.

Never use %reset to start clean. It deletes your variables, but libraries stay loaded and any settings you changed stay changed. It does not give you a clean session. Restart Python instead: Cmd/Ctrl+Shift+0.

If a script only runs after you have run some other thing first, it isn’t finished.
